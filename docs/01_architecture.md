# SPU 微架构

（设计理由与取舍见 `00_design_rationale.md`；RTL 模块级细节与实测周期见 `hw/README.md`。）

SPU（Symbolic Processing Unit）是一个可编程的向量符号（VSA / 超维计算）加速器：符号 = 高维二值超向量，符号结构 = 绑定（XOR）、捆绑（多数表决）、置换（循环移位），推理 = 解绑 + 关联记忆（最近邻搜索），训练 = 累加 + 二值化（含感知机式再训练）。所有原语在 **一条 512 bit 宽的分块数据通路** 上以流水方式执行，由一个小型标量核控制循环和地址，因此完整的训练 / 推理 / 规则求值过程都能作为 **一个 SPU 程序** 自主运行，主机只负责喂数据、读结果。

## 关键设计点

* **分块数据通路**：一个 8192 bit 超向量 = 16 个 512 bit 块。HV 寄存器堆是 BRAM（512 项 × 512 bit，两份拷贝提供 2 读 1 写），每条 HV 指令是 16 拍的微序列 + 流水线排空。资源随 D 线性增长，只改 `Config.D` 即可换到 10 k+ 维。
* **绑定 / 解绑** 是 XOR，**置换** 是跨块的桶形移位（读两块拼接），**捆绑** 走累加器（`ACC_LANES`=128 条 16 bit 加法通道，每次 64 拍），**相似度** 是 XOR + 流水 popcount 树。
* **HGEN**：片上 splitmix64 生成器，8 个 64 bit 字 / 拍。符号不占内存带宽，编译器可以在循环里用 `HGEN(s + base)` 即时生成第 i 个特征 / 字节 / 实体符号。
* **HSEARCH**：关联记忆的核心。从内存流式读取 N 个候选（每个 16 拍，最多 4 个突发在途），与查询缓冲 XOR、popcount、累加得到距离，跟踪最优 / 次优（严格小于更新，平局取小索引），可选把每个距离打包成 512 bit 拍写回内存供标量代码扫描（规则求值就是这样过滤候选事实的）。单核带宽 64 B/拍 ≈ 16 GB/s @250 MHz；HBM2e 可以喂 30+ 个核。
* **累加器**：16 个 D×int16 饱和计数器（URAM），`ADD/SUB` 带 16 bit 权重，`THR` 二值化。既做小规模捆绑（3-5 个向量），也做 HDC 训练的类原型累加与再训练更新，`LD/ST` 可保存 / 续训练。
* **标量核**：非流水多周期（取指 → 译码 → 执行），32 个寄存器，比较跳转、JAL/JALR、字 / 字节访存。它只负责控制流和地址运算，因此简单即可：HV 指令动辄几十到几千拍，标量开销可以忽略。
* **错误与调试**：非法指令 / 累加器越界 / PC 越界 → `ERR` CSR + STATUS.ERR 并停机；主机可读所有标量寄存器、CSR、周期 / 指令计数。

## 时序 / 资源预期（VH1582）

RTL 面向 Versal 250-300 MHz：popcount 树、64 bit 乘法、桶形移位都分了流水级。粗略资源：HV 寄存器堆 ~16 BRAM36 + 累加器 ~8 URAM + 程序存储 8 BRAM36 + 逻辑 ~40-60 k LUT（含 128 路 16 bit 加法和 512 bit 移位器）+ ~150 DSP58（HGEN 乘法）。VH1582 有约 1.9 M LUT / 7 k DSP / 32 GB HBM2e，可放数十个 SPU 核。精确数字以 `build.tcl` 生成的 `utilization.rpt` 为准。

## 每类指令的周期

RTL 实测周期数见 `hw/README.md`（`hw/tb/measure_cycles.py` 可复现）。模拟器 `spuc.sim` 的周期模型已按实测校准：理想内存（延迟 4 拍、无背压）下 HDC 训练与 RTL 相差 0.1%，规则推理相差 10%；带随机停顿的内存模型下搜索密集的规则推理慢约 60%，说明搜索是内存受限的。
