# SPU 芯片架构与设计理由

> 本文回答两个问题：SPU 是什么样的芯片，以及为什么这样设计。ISA 细节见 `02_isa.md`，RTL 模块级说明与实测周期见 `hw/README.md`，上板见 `05_fpga_vhk158.md`。文中所有周期数均来自 Verilator 上的 RTL 实测（内存延迟 4 拍、无背压，除非特别说明）。

## 0. 一页总结

* **问题**：符号主义模型（离散符号、角色-填充结构、关系元组、规则推理、知识记忆与原型学习）的计算是指针追逐、哈希、分支和不规则访存，这类工作在 GPU 上效率低，在 FPGA 上做通用逻辑引擎又会被随机访存拖死。
* **核心决策**：用 **向量符号架构（VSA / 超维计算）** 作为符号的物理表示。符号 = 8192 bit 随机向量；结构 = XOR 绑定、多数表决捆绑、循环移位置换；推理 = 解绑 + 关联记忆（汉明最近邻）；学习 = 计数 + 二值化。所有符号操作都变成 **位并行、无乘法、流式** 的算术，这正是 FPGA 最擅长的。
* **芯片**：一条 512 bit 宽的分块超向量流水线（寄存器堆、逻辑/置换、片上符号生成器）+ 16 个 int16 捆绑累加器 + 流式关联搜索单元 + 一个小型标量控制核 + AXI DMA。单核约 40-60 k LUT，设计频率 250-300 MHz，一个 VH1582 可放数十个核。
* **协同设计**：编译器负责所有静态决策（寄存器分配、tie-break、阈值、表布局、循环结构），硬件因此不需要记分板、乱序或缓存；`isa.py` 是软硬件唯一事实来源；Python 黄金模型与 RTL 逐比特联合仿真。
* **结果**：HDC 分类器训练 / 推理、知识库模式查询、Horn 规则前向链接到不动点、类比推理、复合符号分解，都编译成 **单个自主运行的 SPU 程序**，在 RTL 上与主机参考完全一致。

## 1. 问题定义：符号主义模型的计算特征

符号主义模型的"训练 / 推理"在计算层面可以归结为五种基本操作：

| 符号层面 | 例子 | 传统实现 |
|---|---|---|
| 组合结构 | `capital:paris`，`parent(alice, bob)`，序列 `a b c` | 指针 / 结构体 / 元组 |
| 集合与叠加 | 一条记录的多个属性、一个知识库的多条事实 | 哈希表、索引 |
| 匹配与变量绑定 | `parent(alice, ?Y)`，规则体的连接 | 哈希连接、Rete 网络 |
| 相似 / 类比 / 分类 | "美国的美元相当于墨西哥的什么" | 特征工程 + 分类器，或嵌入 |
| 学习 | 记住新事实、更新类原型 / 规则权重 | 插入索引、梯度下降 |

这些操作的共同点是 **数据依赖的、不规则的访存和分支**：每一步做多少工作、访问哪块内存，都取决于上一步查到了什么。GPU 的 SIMT 模型在这里效率极低；而在 FPGA 上直接实现一个通用 Datalog / Rete 引擎，性能上限由随机访存（哈希连接每个探测一次 DRAM 往返）决定，且训练（学习）没有自然的硬件对应物。

要真正"加速"，需要先换一种表示：让符号操作变成 **规则的、宽的、可流水的算术**，并且推理与学习在同一套算术里。

## 2. 核心决策：用 VSA 作为符号的物理表示

### 2.1 表示与运算

* 每个原子符号是一个 D = 8192 bit 的伪随机二值向量；随机向量两两之间的汉明距离为 D/2 ± √D/2 ≈ 4096 ± 45，即 **高维空间里任意两个符号近似正交**。
* 三种运算构成一个代数：

| 运算 | 定义 | 语义 | 性质 |
|---|---|---|---|
| 绑定 ⊗ | 逐位 XOR | 角色-填充、元组、"A 和 B 一起" | 可逆（⊗ 自身即解绑）、与两个操作数都不相似、保距 |
| 捆绑 ⊕ | 逐位多数表决 | 集合、记录、叠加多条事实 | 结果与每个成分相似（3 路多数相似度 0.75，5 路 0.6875，7 路 0.656） |
| 置换 ρ | 循环移位 | 顺序 / 位置 | 保距、可逆、结果与原向量正交 |

* 推理 = 解绑再清理：`(NAME⊗USA ⊕ CUR⊗DOLLAR ⊕ CAP⊗DC) ⊗ CUR ≈ DOLLAR + 噪声`，用关联记忆（对所有已知符号做最近邻）把噪声去掉。
* 学习 = 计数：把样本 / 事实的编码加进一个整数累加器，阈值二值化得到原型或知识向量；误分类时加真类、减误类即感知机式再训练。

### 2.2 为什么这对 FPGA 是最优的符号表示

1. **位并行、无乘法**：绑定是 XOR，相似度是 XOR + popcount，捆绑是 16 bit 加法。没有浮点，没有乘法（除了符号生成器），LUT 利用率极高。
2. **访存变成流式**：符号表、原型表、事实表都是内存里连续的 1 KB 行，"查找"变成对整张表的顺序流式扫描，AXI 突发和 HBM 带宽被充分利用；不需要哈希、指针和缓存。
3. **推理与学习同构**：训练用的累加器和推理用的搜索共享同一种数据（超向量），不需要两套数据通路。
4. **容错与可控精度**：所有判断都有明确的统计余量（见 2.4），维度 D 是唯一需要调节的旋钮，而且 RTL、模拟器、编译器全部参数化。

### 2.3 覆盖面：五个原语撑起全部前端

| 符号模型 | 编码 | 训练 | 推理 | 前端 |
|---|---|---|---|---|
| 特征-值分类 | `maj_f(ID_f ⊗ L(x_f))` | 累加 + 再训练 | 最近原型 | `hdc.py` record |
| 序列 / 文本分类 | `maj_t(ρ²S_t ⊗ ρS_{t+1} ⊗ S_{t+2})` | 同上 | 同上 | `hdc.py` ngram |
| 知识库事实 | `maj_j(REL⊗ARG_j⊗A_j) ⊕ REL⊗TAG` | 追加到事实表 | 部分匹配搜索 + 解绑 + 清理 | `logic.py` |
| Horn 规则 / Datalog | 同上 | 推导事实写回（不动点） | 嵌套模式求值 | `logic.py` |
| 类比 | 角色-填充记录 | — | 解绑 + 清理 | `01_analogy.py` |
| 复合结构分解 | `X_i⊗Y_j⊗Z_k` | — | 共振器迭代 | `05_resonator.py` |

它们只用到 `HGEN / HXOR / HROT / ACC.* / HSEARCH` 五类指令加标量控制，这就是 ISA 的全部超向量部分——没有为某个模型加特例。

### 2.4 噪声余量（为什么 D = 8192）

随机向量距离的标准差 σ ≈ √D/2 = 45 bit。各类判断的"信号间距"：

| 判断 | 匹配的期望距离 | 不匹配的期望距离 | 间距 / σ |
|---|---|---|---|
| 清理一个 3 路捆绑的成分 | 0.25 D = 2048 | 4096 | 45 σ |
| 事实表部分匹配（2 元关系） | 2048 | 4096 | 45 σ |
| 类比（两次解绑级联） | ≈ 0.375 D = 3072 | 4096 | 22 σ |
| 事实去重（完全相同 vs 差一个参数） | 0 | 2048 | — |
| 共振器首轮（两个 11 路捆绑的乘积） | ≈ 3848 | 4096 | 5.5 σ |

因此 D = 8192 下所有前端用到的判断错误率可以忽略；更深的链式推理或更大的叠加把 `Config.D` 调到 16384 即可（周期数线性增长）。选 8192 而不是常见的 10000 是因为 2 的幂让块索引、旋转拆分和地址计算都退化为位切片。

### 2.5 备选方案与取舍

| 方案 | 表达力 | 可训练 | FPGA 效率 | 风险 | 结论 |
|---|---|---|---|---|---|
| 通用 Datalog / Rete 引擎（哈希连接单元） | 精确逻辑 | 无自然的学习 | 随机访存受限 | 高（连接、递归、索引都要做） | 作为未来的第二类关联单元 |
| 可微逻辑网络（LNN / LTN，t-norm + 梯度） | 模糊逻辑 | 梯度 | 定点 MAC，尚可 | 中；符号结构（变量绑定）弱 | 未选 |
| 嵌入 + 神经网络 | 隐式 | 是 | 需要 MAC 阵列 | 不是"符号主义" | 未选 |
| **VSA / HDC（本设计）** | 符号结构 + 规则 + 相似 | 计数 / 感知机 | 位并行、流式 | 近似（可控） | **选用** |

代价是"概率正确"而非"精确"，以及需要清理记忆；两者都由 D 与阈值控制，并且编译器按多数表决理论自动计算阈值，用户不需要调参。

## 3. 总体架构

```
                 AXI4-Lite (host)                 AXI4 512b master (HBM / DDR via NoC)
                       │                                      ▲
   ┌───────────────────▼──────────────────────────────────────┼─────────────────────┐
   │ spu_top                                                  │                     │
   │  ┌──────────┐   ┌──────────────┐   ┌──────────┐  ┌───────┴───────┐             │

   │  │ CTRL/    │──▶│ 4096 x 64b   │──▶│ unit     │  │ rd/wr engines │             │

   │  │ debug    │        sequencer ───▶│ LW/SW    │  │ outstanding   │             │
```

四条设计原则：

1. **一条宽而简单的分块流水线**：所有超向量运算都是"每拍一个 512 bit 块、16 拍一条指令"，没有第二种数据通路。
2. **关联搜索是一等公民**：推理的主要开销是对表的扫描，所以搜索单元直接挂在 DMA 上流式工作，而不是"加载到寄存器再比较"。
3. **一个小标量核负责一切控制**：循环、地址、分支、条件。它很简单，因为超向量指令动辄 22-90 拍，标量开销被完全掩盖。
4. **编译器承担静态决策**：寄存器分配、捆绑 tie-break、阈值、表布局、循环展开，硬件里没有记分板、没有乱序、没有缓存。

## 4. 逐单元设计与理由

### 4.1 数据通路宽度 W = 512 与分块执行

| 方案 | 每条 HV 指令 | 寄存器堆 | 逻辑 / 移位资源 | 与内存匹配 |
|---|---|---|---|---|
| 全宽 8192 bit | 1-2 拍 | 32 × 8192 触发器 = 262 k FF | 8192 位桶形移位器 ≈ 100 k LUT | 需要 16 拍才能从 AXI 填满一个向量 |
| **512 bit 分块（本设计）** | 16 + 6 拍 | BRAM | ≈ 10 k LUT | 正好等于 AXI/NoC 一拍 |
| 128 bit 分块 | 64 + 6 拍 | BRAM | 更小 | 只用到 1/4 带宽 |

512 bit 是 Versal NoC 对 PL 的最大 AXI 数据宽度，也是 HBM 伪通道一拍的自然粒度：搜索单元每拍消费一个 64 B 拍，寄存器堆每拍读两块写一块，两者对齐让加载、存储和搜索都不需要宽度转换。分块执行让每条指令的成本 = 16 拍 + 流水线深度，这个"常数 + 线性"模型也让编译器的周期估计足够准（理想内存下与 RTL 差 0.1%-10%）。

### 4.2 超向量寄存器堆

* 32 × 8192 bit = 256 Kbit，实现为 **两份相同的 512 × 512 bit 双端口 BRAM**：每份贡献一个读口，两份同时写，得到"两读一写 / 拍"，这是 XOR、AND、旋转（要读两块）需要的最小端口数。触发器方案要 262 k FF，不可行；单份 BRAM 只能一读一写，吞吐减半。
* 32 个寄存器的数量由编译器决定：作用域式分配下，最复杂的前端程序（6 条规则的前向链接）峰值只用 13 个 HV 寄存器；32 留出余量又只占 2 个 BRAM 栈。
* `hbuf`（16 × 512 bit 触发器缓冲）为存储、搜索查询、累加器输入提供一个稳定的操作数副本，避免与寄存器堆读口冲突；也用于 `HROT rd == ra` 这种同名读写的 WAR 冒险（先复制，再旋转，多花 16 拍）。这是"用少量冗余换掉互锁逻辑"的典型取舍。

### 4.3 逻辑与置换

* XOR / AND / OR / NOT / MASK 每拍一块，流水线 RD → EX1 → EX2 → WB，22 拍一条。
* 置换是跨块的循环左移：输出块 j = `(in[j-q] << r) | (in[j-q-1] >> (W-r))`，其中 k = qW + r。两份寄存器堆正好提供这两个源块，两级 512 位桶形移位保证时序。选择"任意位数旋转"而不是"只按块旋转"，是因为 n-gram 编码需要 ρ¹、ρ² 这样的小位移。
* `HMASK`（低 n 位为 1）是一个几乎免费的指令，却让等级编码 `L(v) = L0 ⊗ MASK(v·step)`、加噪、部分置零都不需要查表。

### 4.4 片上符号生成器 HGEN

* **为什么片上生成而不是把"项目记忆"放在 HBM**：符号数量可能很大（每个特征、每个字节值、每个实体一个），用时再从内存读要 26 拍 + 内存延迟且占带宽；片上生成 28 拍且 **可以在循环里生成第 i 个符号**（`HGEN hd, s_i, base`），编译器因此不需要为每个符号分配内存、也不需要在主机上预生成。清理记忆需要的表仍可由同一指令在设备上生成。
* **为什么 splitmix64**：每个 64 bit 字 = `smix64(((seed<<32)|w) ^ GOLDEN)`，纯函数、无状态、8 个字并行；雪崩性好，相邻种子的向量正交。主机（numpy）、模拟器、RTL 三处实现逐位相同，这是所有测试能"逐比特比较"的前提。代价是 8 路 × 2 次 64 × 64 乘法，RTL 拆成 32 × 32 部分积并流水，约 150-200 个 DSP58（VH1582 有 7 k+），如果紧张可减少 `LANES` 换周期。
* 32 bit 种子 = 命名空间 + 索引：编译器为实体、关系、角色、特征等分配不重叠的 2²⁴ 种子段，保证不同族的符号不会撞车。

### 4.5 捆绑累加器

* **为什么用整数累加器而不是逐位多数电路**：3 路多数可以用逻辑做，但训练要把成百上千个样本加进一个类原型，只能用计数器；同一套累加器统一处理"小规模捆绑"和"训练"。
* **int16 饱和**：每次 ADD 使每个计数器变化 ±w；样本数 < 32 k 时不会饱和，饱和只是安全网；再训练用 SUB，且 `-32768` 取负要 18 bit 精确处理（cosim 抓出过这个 bug）。8 bit 太小，32 bit 使存储翻倍。
* **128 通道 × 64 步**：2 Mbit 存储（URAM）每拍读写 2048 bit（128 × 16），是 URAM 宽度和加法器数量的折中：全宽 8192 通道每拍要 130 Kbit 的存储口，不现实；32 通道则 256 拍一条指令，训练变慢 4 倍。实测 ADD 91 拍、THR 73 拍。
* **带权重的 ADD/SUB**：权重来自 `s[rc] + imm`，让 OnlineHD 式的"按相似度加权更新"或学习率不需要新指令。
* **LD/ST**：原始 int16 存到内存，用于保存训练状态、分批训练和主机侧分析。

### 4.6 流式关联搜索 HSEARCH

* **为什么流式**：表（原型、实体、事实）放在 HBM，容量不受片上资源限制；搜索单元通过 DMA 顺序读表，每拍一个 64 B 拍：XOR 查询缓冲 → 4 级流水 popcount → 累加 16 拍得到距离。单核 64 B/拍 = 16 GB/s @ 250 MHz。
* **在途请求**：DMA 允许 8 个突发在途（搜索单元 4 个候选在途），用来掩盖 NoC/HBM 延迟；实测理想内存下 8 个候选 192 拍（8 × 16 + 64 拍启动）。
* **argmin + 次优**：严格小于才更新 → 平局取最小索引（与黄金模型完全一致）；次优距离给出置信度（类比示例中 2991 vs 4020）。
* **WD 模式把每个距离写回内存**：这是让 **标量核参与推理** 的关键——规则求值需要"所有距离小于阈值的事实"而不只是最近的一个。距离打包成 16 个 / 拍，末尾用字节选通写部分拍，标量代码随后按阈值扫描。
* **实测的架构结论**：随机背压 + 最大 24 拍延迟的内存模型下，HDC 训练只慢 6%，而搜索密集的规则推理慢 63%——搜索是内存受限的。这决定了扩展方向：更多在途请求、多路并行搜索（把一张表拆到多个 HBM 伪通道）、以及把小表缓存在片上。

### 4.7 标量控制核

* 非流水多周期核：取指 → 译码 → 执行，顺序后继在执行阶段预取，直线标量代码 2 拍 / 条、跳转 3 拍。
* **为什么这么简单**：实测程序里标量指令占动态指令的大多数，但周期占比很小——HV 指令 22-91 拍、搜索数百拍；HDC 训练每样本 7.6 k 拍里标量控制不到 10%。一个 5 级流水 RISC 核带来的收益不值得增加的冒险处理。
* 32 个 32 bit 寄存器：地址空间 4 GB 窗口（HBM 更大空间通过 64 bit `MEM_BASE` 切换），编译器作用域分配的峰值是 25 个（规则前向链接），因此没有做寄存器溢出。
* 字节加载 `LB` 是为量化特征 / 字节序列编码加的，一条指令替代"加载字 + 移位 + 掩码"。

### 4.8 ISA 设计选择

* **64 bit 定长指令**：6 个字段 + 32 bit 立即数，让地址、种子、阈值、权重都能一条指令表达；程序都很小（最大的前端程序 643 条），代码密度不是问题。
* **统一的 `s[rc] + imm` 值模式**：旋转量、种子、掩码长度、权重、阈值都用它，`rc = s0` 即常数；这让编译器把"循环里的第 i 个符号 / 第 v 个等级"都表达成一条指令。
* **累加器索引是立即数字段**：硬件不用做索引寄存器读取和越界检查路径；训练时按标签选择累加器由编译器生成一串 `if y == k` 分支（每类 2 拍，相对 91 拍的 ADD 可以忽略）。
* **没有超向量立即数、没有 HV 条件执行**：所有"条件"都归标量核，超向量流水线保持无分支。
* **CSR 与错误模型**：搜索结果、性能计数、错误码走 CSR；非法指令 / 累加器越界 / PC 越界 / AXI 错误都停机并报告，主机能读到所有标量寄存器和 CSR，调试不需要波形。
* **程序存储在片上**：4096 × 64 bit BRAM 由主机经 AXI-Lite 写入，取指 1 拍、无缓存、无取指带宽。

### 4.9 存储系统与主机接口

* 32 bit SPU 偏移 + 64 bit `MEM_BASE`：编译器看到的是一个从 0 开始的 4 GB 数据段（`DATA_BASE = 0x10000`），主机把它放到 HBM / DDR 的任何位置（PS 路径下就是 u-dma-buf 的物理地址）。
* HV 访问 64 B 对齐、突发不跨 4 KiB、写为 posted，读在所有写完成后才发出（fence）——保证 `HST → HSEARCH`、`SW → LW` 的程序序，代价是读被无关的写阻塞（已知可优化点）。
* AXI4-Lite 主机口除寄存器和程序存储外，还提供 HV 寄存器分块回读，测试平台正是通过这条真实主机路径导出全部 32 个超向量寄存器做比对。
* `HALT` 等待所有写完成后才置 DONE / 触发中断，主机读结果时内存一定已一致。

## 5. 软硬件协同设计

* **单一事实来源**：`sw/spuc/isa.py` 定义编码、CSR、寄存器映射、配置参数；`scripts/gen_headers.py` 生成 `spu_pkg.sv` 与 `spu_regs.h`。RTL 和编译器不可能漂移。
* **黄金模型**：`spuc.sim` 逐指令实现 ISA，所有架构状态（寄存器、累加器、内存、CSR）与 RTL 逐比特一致；周期数按 RTL 实测校准。
* **联合仿真**：`spuc.cosim` 把同一程序和内存镜像送进 Verilator，比较 32 个标量寄存器、32 个 HV 寄存器、CSR、每一页内存；测试包含 3 组各约 60 条随机指令（随机种子、随机加载 / 存储 / 搜索 / 累加）的差分测试。这一流程找出了 4 个 RTL bug（生成器流水线标签、ACC.LD/ST 启动、SUB 取负精度、测试平台采样时机）。
* **编译器承担静态决策**：
  * 作用域式寄存器分配（无溢出、编译期检测释放后使用）；
  * 偶数捆绑自动追加 tie-break 符号（硬件相等取 0，可预测）；
  * 事实匹配阈值按 k 路多数理论值计算，去重阈值 D/8；
  * 表布局与地址 fixup，循环 / 分支 / `break` 的结构化发射；
  * 主机参考实现（`train_ref`、`evaluate_ref`）与设备程序等价，可逐比特验证。
* **同一 `Binary` 跑在四种设备上**：`SimDevice`、`VerilatorDevice`、`XdmaDevice`（PCIe）、`UioDevice`（Versal PS），前端和示例代码完全不变。

### 6.3 扩展性

* **带宽**：单核搜索 16 GB/s；VH1582 的 HBM2e 约 820 GB/s，可支撑 ~50 个搜索流。多核只需复制 `spu_top`、各自挂 NoC 端口，程序和数据分区由主机分配。
* **维度**：`Config.D` 改为 16384 时，HV 指令周期从 22 变为 38，累加器 128 步，寄存器堆和累加器存储翻倍；编译器阈值自动随 D 变化。
* **资源**（单核，估计）：40-60 k LUT、~16 BRAM36 + 8 URAM（寄存器堆 + 累加器）+ 8 BRAM36（程序）、150-200 DSP58；VH1582 约 1.9 M LUT / 7 k DSP，SPU 核不到器件的 5%。

## 7. 权衡与未采用的方案

| 未采用 | 原因 |
|---|---|
| 全宽 8192 bit 数据通路 | 262 k 触发器的寄存器堆和 100 k LUT 的移位器，且与 512 bit 内存接口不匹配 |
| 用脉动阵列做并行搜索 | 表在 HBM，带宽而非算力是瓶颈；先做多流 DMA 更划算 |
| 片上项目记忆缓存 | 8192 bit × 上千符号超出 BRAM；片上生成器（HGEN）以计算换存储 |
| 整数 / 双极超向量（点积相似度） | 二值 + 汉明覆盖了全部前端，且资源低一个数量级；可作为搜索单元的 MAC 模式扩展 |
| 5 级流水 RISC 标量核 | 标量周期占比 < 10%，冒险处理不值得 |
| 硬件哈希连接 / Rete | 精确但随机访存受限、无学习；作为未来第二类关联单元 |
| HLS 实现 | 需要精确控制流水线、端口和逐比特语义，手写 RTL 更可控且可 Verilator 联合仿真 |
| 累加器索引寄存器间接寻址 | 需要额外读口和越界检查；编译器分支序列开销可忽略 |

## 8. 已知局限与路线图

* 尚未经过 Vivado 时序 / 布局布线（本机无 Vivado）；关注点是生成器乘法链和 128 路 18 bit 加法器，必要时降频到 200 MHz 或增加流水级。
* 单发射、HV 指令之间不重叠；`HST` 多一次 hbuf 复制（+16 拍），`ACC.ST` 未流水。
* 读 fence 等待所有写而非冲突写；搜索受内存停顿影响大（随机停顿下规则推理慢 63%）。
* 类别数 ≤ 15（累加器数量）；更多类别需要累加器内存驻留轮换。
* 前端不做寄存器溢出：规则深度 / 变量数过大时编译器报错而不是降级。
* 路线图：多路搜索流与更深预取 → 多核 + HBM 分区 → 双极 / 整数模式 → 哈希连接单元与 VSA 混合的 Datalog 引擎。
